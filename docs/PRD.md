## 2. 项目背景

新氧连锁医美业务覆盖门店经营、交易、核销、用户、产品、履约、私域、供应链、评价等多个主题，数仓中已沉淀 DIM/DWD/DWS/DM 多层模型与大量指标口径。当前仓库 `soyoung-skills-hub` 已整理出连锁业务背景、49 张核心表、19 个原子指标、132 个衍生指标、NL2SQL 模板和 MaxCompute 查询工具，为构建数据智能助手提供了良好的业务知识基础。

但在实际经营分析中，业务同学常见问题并不只是“某个数是多少”，而是：

- 这个指标应该用哪张表、哪个字段、什么过滤条件？
- 同一个“收入”到底是核销收入、核销 GMV，还是支付 GMV？
- 毛利率下滑到底是收入结构、耗材成本、手工费，还是让利补贴导致？
- 0 元单、门店改价、用户运营券、L0 灌券等问题如何快速定位？
- 数据开发同学如何减少重复答疑，把标准口径沉淀成可复用能力？

因此，本项目计划基于 Doris + LangChain 构建一个用于展示和学习的“连锁数据智能运营助手”。系统通过 RAG 检索业务知识、指标字典和 SQL 模板，结合 MaxCompute 只读查询能力，为用户提供自然语言问数、标准 SQL 生成、指标解释和毛利率诊断分析。

## 3. 核心痛点

### 3.1 找数难

连锁业务表分布在交易、用户、门店、产品、供应链、私域等多个主题中。即使只分析毛利率，也会涉及：

- 毛利率主表：`dws_opt_qy_gross_margin_stats_all_d`
- 核销宽表：`dm_opt_qy_user_execution_record_all_d`
- 耗材成本底表：`dwd_ord_order_qy_execution_record_cost_all_d`
- 优惠券、用户等级、门店补贴、老带新成本等辅助表

新人很难快速判断主表、明细表和辅助表的边界。

### 3.2 口径易错

连锁经营分析高度依赖统一口径。例如：

- 毛利率必须使用 `SUM(毛利额) / SUM(NULLIF(核销收入, 0))`，不能逐行计算后平均。
- 耗材成本当前只计入高值耗材，`consumable_type IN (1,3)`。
- 客单价分母是核销人次 `verify_date_id`，不是客户数 `customer_id`。
- `_all_d` 表需要区分 `dp` 快照日期和业务发生日期。
- 大师团、绿标品、常规品需按互斥优先级分类。

口径错误会导致结果看似合理，但实际无法用于经营判断。

### 3.3 诊断链路长

以毛利率分析为例，业务方关心的不是单个指标，而是一条完整诊断链路：

1. 大盘毛利率是否达成 48% 目标。
2. 三类品收入结构是否变化。
3. 耗材率和手工费率是否异常。
4. 让利补贴是否超目标。
5. 哪些品项、门店、会员等级拖累毛利。
6. 应采取什么经营动作。

传统方式需要人工查 SQL、拉表、做透视、写结论，耗时较长。

### 3.4 重复答疑多

数据同学需要反复回答“指标怎么算”“为什么数不一致”“用哪张表”“SQL 怎么写”等问题。项目希望把这些高频答疑沉淀进知识库和 Agent 流程中，降低重复沟通成本。

## 4. 产品目标

### 4.1 业务目标

- 帮助用户用自然语言完成连锁业务问数和毛利率诊断。
- 将指标字典、表结构、SQL 示例和业务分析 SOP 统一沉淀为可检索知识库。
- 降低数据开发和经营分析同学的重复答疑成本。
- 为实习项目展示提供一个与真实连锁业务结合紧密的 Agent 应用案例。

### 4.2 学习目标

- 熟悉 Doris ANN 向量检索的基本使用。
- 熟悉 LangChain 在 RAG、工具调用、Prompt 编排中的作用。
- 熟悉 Flask Web 应用的前后端交互。
- 熟悉 MaxCompute 只读查询、安全校验和 SQL 生成流程。
- 熟悉连锁业务指标口径和毛利率专题分析方法。

### 4.3 MVP 成功标准

- 用户可以在聊天页提出 5 类高频问题，并得到结构化回答。
- 系统能够返回指标口径卡片、SQL、结果摘要和业务解释。
- 毛利率诊断场景能按照“总量-结构-成本-补贴-下钻-建议”的链路输出。
- 管理员可以上传或同步业务知识，并重建 Doris 向量库。
- 所有密钥和真实数据均不进入 GitHub 仓库。

## 7. 核心业务场景

### 7.1 指标口径问答

用户问题示例：

- “核销收入和支付 GMV 有什么区别？”
- “品项毛利率怎么算？”
- “客单价为什么要用核销人次做分母？”
- “绿标品、常规品、大师团怎么分类？”

系统输出：

- 指标定义。
- 计算公式。
- 推荐源表。
- 必加过滤条件。
- 常见错误提醒。
- 引用知识来源。

### 7.2 自然语言取数

用户问题示例：

- “昨天连锁核销收入是多少？”
- “近 30 天新客和老客收入、客单价分别是多少？”
- “上月私域、公域、老带新的核销人次分别是多少？”
- “BBL HERO 近 90 天渗透率是多少？”

系统输出：

- 需求复述。
- 口径卡片。
- 生成 SQL。
- 查询结果。
- 口径与假设说明。

### 7.3 毛利率诊断

用户问题示例：

- “帮我复盘一下 5 月品项毛利率。”
- “为什么本月毛利率下降？”
- “常规品毛利率低是成本问题还是补贴问题？”
- “L0 用户灌券对毛利影响大吗？”
- “哪些门店毛利率异常？”

系统输出结构：

1. 大盘总览：毛利率、核销收入、目标差距、趋势判断。
2. 收入侧：大师团、绿标品、常规品收入占比与毛利率。
3. 成本侧：耗材率、手工费率、成本异常。
4. 补贴侧：促销补贴、门店改价、用户运营券、历史价差。
5. 下钻侧：品项、门店、会员等级异常 TopN。
6. 诊断结论：正向信号、风险信号、建议动作。
7. 口径声明：数据源、分类规则、耗材口径、时间分区。

### 7.4 表字段查询

用户问题示例：

- “毛利率主表有哪些字段？”
- “让利补贴字段在哪张表？”
- “耗材成本怎么关联核销记录？”

系统输出：

- 表名与业务用途。
- 关键字段说明。
- 关联键。
- 使用注意事项。
- 示例 SQL。

### 7.5 管理端知识维护

管理员操作：

- 上传 Markdown、SQL、HTML、Excel 摘要文档。
- 查看已入库知识文件。
- 触发文档切分和向量构建。
- 查看 Doris 向量库状态。
- 查看 MaxCompute 元数据同步时间。

## 12. Prompt 设计要求

### 12.1 通用系统 Prompt

系统应明确：

- 你是新氧连锁医美业务的数据智能运营助手。
- 回答必须遵循指标字典和业务口径。
- 不确定口径时必须说明假设或追问。
- SQL 只允许只读查询。
- 分析结论必须基于查询结果和检索知识。

### 12.2 毛利率诊断 Prompt

必须要求模型按以下结构输出：

1. 大盘总览。
2. 收入侧结构。
3. 成本侧结构。
4. 补贴侧结构。
5. 异常下钻。
6. 结论与建议。
7. 口径声明。

必须包含以下口径：

- 品项毛利率 = `SUM(gross_margin_amt) / SUM(NULLIF(exe_income, 0))`
- 毛利额 = `exe_income - ware_cost - manual_fee`
- 耗材只含高值耗材。
- 三类品分类优先级：大师团 > 绿标品 > 常规品。

## 18. 附录: 毛利率核心口径

### 18.1 品项毛利率

```sql
SUM(gross_margin_amt) / SUM(NULLIF(exe_income, 0))
```

其中：

```text
gross_margin_amt = exe_income - ware_cost - manual_fee
```

### 18.2 三类品互斥分类

```text
大师团 > 绿标品 > 常规品
```

### 18.3 六步复盘法

1. 看总量：毛利率、收入、目标差距。
2. 拆收入侧：大师团、绿标品、常规品。
3. 拆成本侧：耗材率、手工费率。
4. 拆补贴侧：促销补贴、门店改价、用户运营券、历史价差。
5. 下钻异常：品项、门店、会员等级。
6. 交叉判断：输出结论和动作建议。

### 18.4 关键风险项

- 常规品收入占比高但毛利率长期低位。
- 0 元单使用高值耗材会直接拖累毛利。
- L0/L1 低等级用户补贴效率低，存在灌券风险。
- 门店改价和促销补贴超目标会侵蚀利润。
- 数仓和财务口径可能因耗材范围不同产生 1-4pp 差异。
